TOMB5 engine limits (fixed buffers/arrays, filled from level data) - as of 2026-08-02.
All spots listed below meanwhile have a bounds check (see TOMB5 Code commit df39071) -
levels that exceed a limit now abort cleanly with an error message instead of silently
corrupting memory. The numbers themselves are still the actual upper bound the
randomizer must respect.

1# Item level limit 256 (MAX_ITEMS, global\types.h) - number of items/moveables per level.
   Only the check was added, the size deliberately NOT raised (should suffice for the
   randomizer).

2# Texture page limit 256 (Textures[], specific\texture.cpp/.h) - RTPages+OTPages+BTPages+1.
   Was originally only 64 - THAT was the case I had remembered. Raised to 256 AND given a
   check. Important in case the randomizer combines textures from several source levels.

3# Spotcam limit 256 (SpotCam[], specific\file.cpp) - number of spot cameras per level.
   Only the check was added, size unchanged.

4# Animated UV texture ranges limit 16 ranges x 8 entries (AnimatingTexturesV[16][8][3],
   specific\file.cpp, S_GetUVRotateTextures) - rotating/conveyor-like textures.
   Only the check was added, size unchanged.

5# Sound sample limit 256 (DS_Buffers[], specific\dxsound.cpp) - number of sound samples
   per level. Only the check was added. IMPORTANT: the engine itself assumes up to 450
   possible samples elsewhere (sample_lut, MAX_SAMPLES=450, global\types.h) - so this
   buffer was already tighter than the rest of the sound system expects. If the
   randomizer builds in its own SFX for new/changed enemies, keep an eye on this.

6# Room limit 256 (flipped[], game\setup.cpp, BuildOutsideTable - a STACK array, not heap!)
   Only the check was added, size unchanged. Concerns the total number of rooms per level
   (number_rooms), not directly items/enemies - only relevant if the randomizer ever
   merges/extends level geometry.

7# ItemNewRooms[256][2] (game\control.cpp/items.cpp) - per-frame queue for room
   changes/deaths of items+effects during the item control loop. NOT a level load-time
   limit but runtime: more than 256 simultaneous room changes/deaths in ONE tick would
   overflow. An extremely rare edge case, hence secured only with a soft skip+log instead
   of a hard abort. Keep in mind for very dense randomizer setups (many simultaneously
   reacting enemies), but low priority.

8# Savegame buffer 14490 bytes (SAVEGAME_INFO::buffer, global\types.h) - doubled from
   originally 7245. Grows proportionally to the number of active/triggered items at save
   time (roughly 90-110 bytes per fully active AI enemy). Overflow guard + checksum check
   on load added (details: project_tomb5_native_port.md, project_trviewer_tr5.md).

9# Regenerating pickups limit 16 (RPickups[], game\pickup.cpp) - items with
   trigger_flags&0x80 (auto-respawn flag). Soft skip instead of abort (only a cosmetic
   effect loss, no memory problem), low priority for the randomizer.
