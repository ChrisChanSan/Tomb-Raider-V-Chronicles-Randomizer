# Secret list for the TR5 Randomizer.
#
# File name = Author_Category.txt - the author appears that way in the
# dropdown of the respective category (Glitchless or Glitched). Whoever
# wants to contribute their own list simply puts another file into this
# folder.
#
# Columns:
#   Level             file name of the level
#   Count             how many secrets the level has (a cross-check)
#   Type_ID           223 = secret
#   Level_ID          the item indices of the secrets in the vanilla level
#   New_Rooms/Sector  where they should go, in the same order as Level_ID.
#                     Empty = this level stays vanilla.
#   Extra_Options     additional items, triggers and geometry. Separate
#                     several groups with ";" (unambiguous); the old "+" is
#                     still read. What the reader does not understand it
#                     reports - a mistyped "@Angel0" does not vanish
#                     silently.
#
#                     EIGHT FORMS:
#
#                     1) Append an item
#                        add Type_ID(<type>)@Room<N>(x<A>,z<B>)
#                        Instead of room+sector, the place of an existing
#                        item also works:  @LikeItem(<item>)
#
#                     2) Only a trigger, without an item
#                        add Trigger_Type(Trigger)@Room<N>(x<A>,z<B>)
#                            to->... Item_Level_ID(<targets>)
#
#                     3) Retype an existing item
#                        replace Item_Level_ID(<item>)with->Type_ID(<newType>)
#                        Without @Room the place stays; WITH @Room(x,z) the
#                        item moves (sector center, floor height computed).
#
#                     4) Portal - open a sealed passage on both sides
#                        Make_Portal@Room<A>(x,z)->Room<B>(x,z)
#                        Make_Ceiling_Portal@Room<A>(x,z)->Room<B>(x,z)
#                        Make_Floor_Portal@Room<A>(x,z)->Room<B>(x,z)
#                        The "->" is pairing, not direction: ONE line opens
#                        both sectors onto each other. The view window must
#                        already exist in the level, otherwise an error.
#                        WALL, CEILING and FLOOR are three separate words on
#                        purpose - letting the reader guess the direction
#                        from the geometry is what broke andy1.
#                        ("Celing" is tolerated, spelled either way.)
#                        Two extras belong to the portal forms only:
#                          @Clear                     remove the drawn wall
#                                                     face on both sides
#                          @LikeWall(Room<N>(x,z))    take the surrounding
#                                                     wall's look from there
#
#                     5) Climbing wall
#                        Make_Climb@Room<N>(x<A>,z<B>)@Angle(<degrees>)
#                        Angle = Lara's LOOK at the wall. Quarters only
#                        (0/90/180/270). Several lines on the same sector
#                        add up their directions.
#
#                     6) Flood or drain a room
#                        Make_Room_Water(<room>)   resp.
#                        Make_Room_Nowater(<room>)
#                        A real intervention: 44 places in the engine hang
#                        on the water bit (swimming, camera, sound, AI
#                        paths, fire).
#
#                     7) Move a whole room
#                        Move_Room<N>(x=<a>, y=<b>, z=<c>)
#                        Any axis may be left out. PLUS RAISES: y is written
#                        the way a level editor reads it, and the reader
#                        turns the sign round for the file, where y grows
#                        downward.
#
#                     8) Give a room that has none a drawn surface
#                        Make_Room_Geometry<N>(like=Room<M>)
#                        76 rooms in Chronicles have no geometry at all -
#                        vertex and face block are zero bytes long, Lara
#                        walks on the floor and you look into black. This
#                        lays a surface over what the sector data already
#                        says, so what you see is what you walk on; the
#                        floor data itself is not touched. A room that
#                        already carries faces is left alone.
#                        Keys, all optional, in any order:
#                          like=Room<M>    take the textures from that room
#                                          (the commonest one it uses for
#                                          floor, ceiling and wall)
#                          floor=<t>       name the texinfo outright,
#                          ceiling=<t>     instead of or on top of like=
#                          wall=<t>
#                          floortri=<t>    the same for TRIANGLES. A texinfo
#                          ceilingtri=<t>  carries the shape it was cut for,
#                          walltri=<t>     so a triangle wearing a quad's
#                                          number maps wrongly. like= brings
#                                          its triangles along; without it
#                                          these are needed as soon as a
#                                          split sector or a wall running out
#                                          at one corner makes one.
#                          x=<A>, z=<B>    only that square
#                          band=<k>        only that band of the wall,
#                                          counted from the FLOOR upward
#                        Lines for the same room ADD UP: the first is the
#                        rule for the whole room, every later one an
#                        exception to it.
#                          (Make_Room_Geometry74(like=Room1))
#                          ; (Make_Room_Geometry74(x=2, z=2, floor=2290))
#                          ; (Make_Room_Geometry74(x=0, z=2, band=3, wall=2292))
#
#                     EXTRAS (forms 1 and 3):
#                       @OCB(<value>)    object code. On switches it decides
#                                        where Lara has to stand!
#                       @Angle(<deg>)    in DEGREES, parentheses optional
#                       @Height(<value>) that many units HIGHER
#                       @XOff(<value>)   offset in X
#                       @ZOff(<value>)   offset in Z
#                     Form 1 only:
#                       Trigger_Type(Key|Switch|Pickup)to->... Item_Level_ID(<targets>)
#
#                     Item_Level_ID takes SEVERAL targets, separated by
#                     commas. A target is an existing item index or "New<k>"
#                     - the k-th item THIS line creates itself. With it, an
#                     item just created can be addressed whose index cannot
#                     be known while writing.
#
#                     Example of a double door, one switch for both halves:
#                       (replace Item_Level_ID(13)with->Type_ID(284)@Angle90)
#                       ; (add Type_ID(284)@LikeItem(13)@Height(1024)@Angle90)
#                       ; (add Type_ID(266)@OCB(8)@Room202(x2,z1)@Angle270
#                          +Trigger_Type(Switch)to->Door Item_Level_ID(13, New1))
#                       ; (Make_Portal@Room34(x0,z5)->Room36(x4,z5))
#
#                     The "+" BEFORE Trigger_Type belongs to the group and
#                     stays.
#
#                     NOTE 2026-08-30: this example used to say
#                     @Room202(x1,z1). That is the andy3 sector the reader
#                     itself warns about - it carries TILT, and a switch on
#                     a slope cannot be operated. It is the case the warning
#                     below was written for, so it is a poor thing to copy.
#
# PITFALLS that are hard to find in game:
#   - Switches and keyholes need LEVEL floor. Their position window is zero
#     wide in Y; on a slope Lara takes many heights and never hits the one.
#     All 72 vanilla switches stand level. The reader warns when a type
#     258..274 lands on a slope.
#   - Trapdoors must stand on their room's portal plane (minfloor resp.
#     maxceiling), otherwise they seal nothing and Lara falls through.
#     Ceiling trapdoors belong into the LOWER room.
#   - No wall grab (OCB 2/9) near an enemy: he carries it off when dying,
#     after which it can no longer be picked up. The randomizer bars that
#     for its own placements, this list does not.
#
# A secret moved through New_Rooms/Sector also has its OCB reset and its
# invisible flag cleared. Vanilla hides some secrets behind an OCB that only
# makes sense where they originally stood, and they would be unpickable
# anywhere else.
#
# The height is not given - the randomizer computes the sector's floor
# height itself, also on slopes.
